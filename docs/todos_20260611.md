## Plans for Development
The goal of the diffice package is to perform inversion of ice viscosity for ice shelves (floating) and viscosity along with basal friction for ice streams(grounded). To invert for ice stream basal friction, the viscosity must also be simultaneously inverted for (in general). This is referred to as joint inversion. To perform a joint inversion, an ice shelf must be coupled to an ice stream, so that the viscosity boundary conditions are known at the grounding line, where ice streams begin to float and form ice shelves. Hence, there are at least two separate regions in a joint inversion always. We can restrict ourselves to this special case of a two-region, joint inversion of viscosity and basal friction for now.

The most recent efforts have focused on developing the two-region (one being ice stream, the other being ice shelf) joint inversion workflow using x-pinns as in `tests/test_xpinn_regression`. To do so, the workflow and the loss function have been hard-coded to work with data that contain ground-truth viscosity and friction data, which is normally not available for real datasets. This style of development is tagged with the word "regression." I would first like a few options to make the `loss_regression_create` loss function fully compatible with real datasets, removing all the parts that real datasets would not work with. This will make the new x-pinn loss function for a two-region inversion. The functionality should stay exactly the same as when the weights on the viscosity and friction data loss is exactly zero in the `loss_regression_create` loss function. 

Next, the code for the kfac optimizer as of now is extremely messy due to a need to register loss functions. I have been told that it is possible to simply register a mean-squared loss function, and then simply use that function across all the different branches in `loss_regression_create` or other loss functions. I want the clutter gone and easy modifications.

Then, the standalone pinns are largely neglected in this development, and there may be mismatches between the x-pinn code and the pinn code. The pinn code cannot do joint ice-stream ice-shelf inversion, and it must do either only ice shelf inversion, or only ice stream inversion but with the viscosity provided at the GL as a boundary condition. For instance, a new version of SSA to be added in the future depends not on the thickness `h` but on both thickness `h` and surface elevation `s`, in addition to velocities `u` and `v`.   6. KFAC simplification is plausible, but the details matter.

  KFAC-JAX’s docs say the optimizer needs registered losses to approximate curvature correctly, and it supports register_squared_error_loss and register_normal_predictive_distribution. The
  squared-error registration assumes a loss like weight * sum((target - prediction)**2) / batch_size, not plain mean((target - prediction)**2) across all dimensions, and it warns that prediction
  must be parameter-dependent while targets must not be parameter-dependent. Source: KFAC-JAX API docs (https://kfac-jax.readthedocs.io/en/latest/api.html#kfac_jax.register_squared_error_loss),
  KFAC-JAX README (https://github.com/google-deepmind/kfac-jax).

  So the likely clean design is: build one weighted residual vector, register it as prediction=residuals, targets=zeros_like(residuals), and make the scalar objective exactly match the registered
  convention. But this must be verified numerically against the current KFAC objective.

  Go ahead with your recommendation.
