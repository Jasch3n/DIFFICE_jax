# Region construction splits into a shelf-class strategy registry, not more `if config.X` branches in `build_regions`

`domain.build_regions` mixes a shared skeleton (raw polygon load, GL load, calving-front load/trim, normals, velocity reconciliation, cut-boundary computation, `DomainRegions` assembly) with shelf-class-specific geometry (GL flow-filtering, a velocity-thresholded grounded corridor, near-interface smoothing with a GL-protection radius, grounded/floating overlap resolution) via `if config.grounding_line_min_speed_myr is not None` / `if config.grounded_corridor_margin_km is not None` branches inside one ~170-line function. Every Ross East/Byrd fix documented in `HANDOFF.md` edited this one function body, and each carried a real risk of silently changing Amery's output — the only guard against that was manually re-diffing Amery's `.mat` counts after each change, not something the code structure enforced. `floating_region.py` already solved the equivalent problem for *how far the floating region extends* (a contract + registry, mirroring the `data_sources/*` pattern); the grounded/GL half of the same problem never got the same treatment.

We chose to complete that pattern: a new `REGION_STRATEGIES` registry (keyed by new `PipelineConfig.region_strategy`, default `"simple"`) holds one function per shelf-class, each with the signature `(config, basin_raw, shelf_raw, gl) -> RegionShape`. `build_regions` becomes a shared prologue (load raw polygons, load GL, bootstrap-buffer the grounded region, trim GL to the interface) → the strategy call → a shared epilogue (front load/trim, normals, velocity reconciliation, cut boundaries, `DomainRegions` assembly), identical for every shelf-class. `process_simple` (today's Amery-class default) contains none of the flow-filter/corridor/smoothing machinery and cannot reference it; `process_flow_restricted` (today's Byrd-class) owns all of it, including deriving one `flow_speed_myr` value into the GL filter, the grounded corridor, and the floating-region seed threshold — replacing today's hand-synced `grounding_line_min_speed_myr` / `floating_region_kwargs.min_normal_velocity_myr` pair, which had no mechanism preventing them from drifting apart.

## Considered options

Three interface shapes were designed in parallel (see the "design it twice" comparison in-session) before choosing:

- **Minimal single-seam interface** — a frozen `RegionInputs`/`RegionGeometry` pair around one strategy call, maximum leverage per entry point. Close to what we chose, but its prologue/epilogue split fed the *raw* basin polygon forward into the shared epilogue's calving-front load and velocity reconciliation — silently wrong for the flow-restricted strategy, whose basin is deliberately smoothed by that point (`_smooth_near_interface`). We adopted this design's frozen-contract discipline but not its choice of what the contract carries.
- **Composable stage pipeline** — every operation (`_filter_gl_by_flow`, `_smooth_near_interface`, `_grounded_corridor`, …) becomes a `Stage(name, run, requires, produces)`; a shelf-class is an ordered list of stages, statically validated before running. Maximizes future flexibility (reorder/insert/skip stages without the driver knowing) but, by the design's own honest assessment, its leverage is *latent* at two shelf-classes — the `requires`/`produces` metadata validates field presence, not the semantic invariant that actually matters ("the basin polygon must stay unsmoothed through GL loading and streamline tracing"), which is exactly the invariant every real Byrd bug in `HANDOFF.md` turned on. Rejected for now as over-engineering relative to N=2; revisit if a third shelf-class's needs don't fit the two-strategy split.
- **Two-tier trivial-default / opt-in-specialized (chosen, refined)** — same registry seam as the minimal design, but the intermediate contract explicitly carries whichever basin polygon (raw or smoothed) the shared epilogue should see, and the config surface collapses shelf-class knobs into one `region_strategy_kwargs` dict so a plain new shelf needs zero geometry fields. This is what we implemented.

## Consequences

- `PipelineConfig` gains `region_strategy: str = "simple"` and `region_strategy_kwargs: dict`; `grounding_line_min_speed_myr` and `grounded_corridor_margin_km` move from top-level fields into `region_strategy_kwargs`, read only by `process_flow_restricted`. `configs/ross_east_byrd.yaml` needs updating to the new field names; a plain new shelf/zone config needs none of them.
- `floating_region.py` is unchanged and stays its own independent registry — `process_flow_restricted` calls it (passing the derived `min_normal_velocity_myr`) the same way `build_regions` does today; `process_simple` calls it with `whole_shelf`'s existing defaults untouched.
- Adding a third shelf-class means writing one new `process_*` function and one registry entry, with zero edits to `process_simple`, `process_flow_restricted`, or the shared prologue/epilogue in `build_regions`. If a future shelf needs only *some* of the flow-restricted machinery (the "mostly simple but needs one Byrd-ish knob" case), the two-strategy split has no in-between — the honest cost of this design is that such a shelf needs a new named strategy rather than composing existing knobs à la carte.
- Because two of the four operations moved into `process_flow_restricted` (`_smooth_near_interface` on the floating polygon, `grounded_polygon.difference(floating_polygon)`) run *unconditionally* in today's `build_regions`, including for Amery, this refactor's safety depends on confirming they are true no-ops for Amery's `whole_shelf` case before landing — not assuming it. A frozen-baseline diff harness for the three existing Amery `.mat` outputs is being added alongside this change specifically to make that a mechanical check rather than a manual one, per `HANDOFF.md`'s own open item ("no dedicated byte-for-byte diff was done for this specific change... worth doing if Amery ever looks different").
